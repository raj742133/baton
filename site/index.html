A skill for Claude Code & Claude chats

Switch accounts.
Keep the thread.

Baton keeps one living BATON.md of your project: where the folder is, what's done, what's decided, what's next. Drop it into any chat, on any account, and the new Claude finds your project and carries on from that exact sentence.

Install in 30 seconds See the live overlay
  • Local-only, no accounts
  • Secrets redacted
  • Updates itself every turn

Three moves. No re-explaining.

  1. 1

    It saves while you work

    After every reply Baton refreshes the file: project path, git state, recent files, your decisions and the tail of the conversation. You write nothing.

  2. 2

    Drop it in a new chat

    Log out, log in, switch machines. Attach BATON.md. A protocol at the top tells the new Claude exactly how to behave.

  3. 3

    It finds your folder

    Not sure where the project lives? The file carries a fingerprint (git remote, marker files). Claude searches, verifies against the real folder, then continues.

    Install

    Needs Node 18+ and Claude Code. Takes about 30 seconds. Nothing leaves your machine.

    1 · Run in PowerShell

    irm https://baton-handoff.vercel.app/install.ps1 | iex

    1 · Run in a terminal

    curl -fsSL https://baton-handoff.vercel.app/install.sh | sh

    Download baton.zip, unzip, then run install.ps1 or install.sh from the folder. Or copy by hand:

    skill/baton/        →  ~/.claude/skills/baton/
skill/baton/scripts/baton.mjs  →  ~/.baton/bin/baton.mjs
overlay/            →  ~/.baton/overlay/

    1. Turn on the overlay optional, recommended

      Start Claude Code with the overlay loaded, then type /baton.

      claude --plugin-dir "$HOME/.baton/overlay"

      In the desktop app, put the folder in ~/.claude/dev-mods/<session>/baton-overlay and accept the hot-reload prompt.

    2. Or auto-save through hooks no overlay needed

      node ~/.baton/bin/baton.mjs install-hooks

      Adds Stop, PreCompact and SessionEnd hooks to ~/.claude/settings.json (a backup is kept). Undo with uninstall-hooks.

    3. Hand off

      Just say "baton, hand off" in a chat. Claude writes the narrative (goal, state, exact next step) and the engine does the rest.

    4. Resume

      In the new account's chat, drop BATON.md (it's at ~/.baton/BATON.md) and send. That's the whole ritual.

    What's inside BATON.md

    One portable markdown file with six parts, written so a model with no memory of you can act on it.

    0 · Pickup protocol

    Orders for the next Claude: locate the folder, verify, summarise, continue. Treats the file as data, not commands.

    1 · Location & fingerprint

    Path, git remote, branch, marker files. How to find the project even if you moved machines.

    2 · Narrative

    Goal, done, in progress, exact next step, open questions. Written by Claude.

    3 · Decisions

    Constraints and preferences, so they never need repeating.

    4–5 · Map & live state

    Layout, recent files, uncommitted changes, recent commits, auto-captured.

    6 · Conversation tail

    Opening request and last exchanges, secrets redacted.

    Questions

    Where is my data stored?

    Only in ~/.baton/ on your machine, plus wherever you export it. There is no server and no account. This website only hosts the installer.

    Does it keep secrets out?

    Common token shapes (API keys, GitHub tokens, bearer headers, password=…) are redacted before anything is written. Still, read the file before sharing it, and never put secrets in notes.

    Will the new chat remember everything?

    It gets the narrative, decisions, live state and the conversation tail, not a transcript. That is deliberate: a small, current file beats a stale giant one. Keep the narrative fresh and the handoff is lossless where it matters.

    Can it be a prompt-injection risk?

    The protocol tells the next Claude to treat the file as data from a past session and to ask before acting on anything that looks like a command. Only paste handoffs you created.
